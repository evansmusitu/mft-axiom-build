## Failure and evidence boundaries

No ambiguous initializer or provider mutation is automatically retried. A prior script/checkpoint/once-only guard is a HOLD, never permission to reset/delete/reuse the namespace. Failure after an attempted upload triggers temporary-control retirement and exact serving restoration while preserving all authority state. If the PC or provider disconnects, retain the owner-signed request journal. The same file's retirement-only mode accepts only a valid prior owner journal from this exact source and a currently recognized bundle, removes temporary controls and rotates test roles without reinitializing or erasing state. A separately reviewed continuation is required to resume an incomplete ceremony.

`RETURN_ONLY` contains signed public receipts and the request-method/path/status journal. Original provider bytes and private tail events are AES256-GCM encrypted separately on the PC; a random session key is wrapped with Windows DPAPI CurrentUser under owner/SYSTEM-only inherited NTFS permissions. They never enter `RETURN_ONLY`. Preserve this private archive for local independent review; do not upload it to chat. Loss of private capture stops further mutations except owned retirement and prevents a completion result.

Every result preserves `gate3_closed=false`, `B27=FAILED_IN_SYNTHETIC_ATTACK`, `parity_superiority=NOT_CERTIFIED`, unavailable final usage `UNKNOWN` and `NOT_RELEASE`. An operator signature proves which key signed a receipt, not independent custody or final independent acceptance. This automation provides concrete operations and reviewable evidence; it does not grant itself release authority.
