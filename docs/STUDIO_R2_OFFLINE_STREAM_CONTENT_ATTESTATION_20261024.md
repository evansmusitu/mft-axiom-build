# Studio V0.3 — bounded byte-level R2 reconciliation (24 October 2026)

**Status: SOURCE-ONLY. No Cloudflare/R2 read was performed; production SQLite DO remains authoritative.**

The pre-existing ledger reconciliation uses authenticated HMACs over database rows, including R2 object keys, SHA-256 metadata and byte counts. This is insufficient to prove that stored R2 object bytes still exist, are readable, or match their declared hashes. The new `musitu_studio/neon/r2_content_reconcile.mjs` module introduces `verifyStudioR2ObjectBytes` for offline, explicit, read-only verification of every R2 asset referenced by a **complete and normalized, frozen** Studio V0.3 ledger. It is not connected to the production Worker or billed providers.

The caller supplies a verified source snapshot, a 256-bit minimum HMAC key, and an independently authenticated `readObject` function. The function validates the entire source ledger and canonical Studio asset keys, establishes an up-front 128 MB default byte budget (caller may explicitly change it), and stream-hashes all referenced object bytes. Each object must match both its exact byte count and independent SHA-256 digest. Missing objects, corrupted equal-size objects, wrong chunk types, reader exceptions, truncation, additions, and budget overrun fail closed. It returns a privacy-safe aggregate HMAC receipt domain-separated by schema/freeze epoch and bound to the ledger assets-table HMAC, not customer content or object keys. The receipt *always* records `provider_verified:false` and `cutover_authorized:false`.

**Remaining mandatory qualifications:** This source-only API cannot independently authenticate the reader, prove the Cloudflare R2 bucket identity or object-version stability, validate an exclusive SQLite freeze, detect unrelated unreferenced R2 objects, attest real R2 billing/limits, restore a hosted database, ensure private Neon connectivity, or authorize a production cutover. A future gated adapter must enforce each condition, use immutable/versioned reads where supported, and capture real provider receipts without recording customer payloads. Do not run against customer R2 without protected owner approval and spending controls.

**Offline tests:** `node --test musitu_studio/neon/tests/r2_content_reconcile.test.mjs`. Full Neon suite: `node --test musitu_studio/neon/tests/*.test.mjs`. The tests use exclusively synthetic in-memory object streams.
