# MUSITU Enterprise Studio V0.3 — Owner-authenticated source freeze contract
**Date: 2026-10-22. Status: STAGING-ONLY source implementation, not deployed.**

## Scope and actual verification

This isolated-branch change repairs a serious gap in the source-only migration exporter. Previously `readFrozenStudioDoLedger()` accepted `writesFrozen:true` and `staffJwtVerified:true` as caller-supplied assertions without verifying that SQLite itself blocked writes. A production snapshot might consequently be marked complete while new jobs or audits were being created.

New `musitu_studio/neon/do_source_freeze.mjs` contains an **UNINSTALLED** SQL setup string with 15 `BEFORE INSERT/UPDATE/DELETE` triggers for the five canonical ledger tables: `projects`, `memberships`, `jobs`, `assets`, `audit_events`. The triggers require the `active` short-lived SQLite `_studio_export_freeze` row (owner subject SHA-256, one cryptographically random UUID, issued/expires epoch). They reject mutations with `STUDIO_MIGRATION_WRITES_FROZEN`. Max allowed TTL is **300 seconds** (configurable 10–300, default 120); expired leases automatically cease to block writes, and cannot authorize stale exports. The release operation only accepts the same signed owner and freeze UUID, and rejects superseded epochs. The matching owner's database membership is verified inside the transaction. This is not a web-accessible API.

`readFrozenStudioDoLedger()` **now fails closed** if the source table freeze is absent, expired, wrong-owner, wrong UUID, version!=2, or any trigger is missing/altered. It performs source-fence checks *inside the same synchronous SQLite transaction* both before and after the five-table read. It retains all earlier caller identity, row/byte cap and schema defenses. A fabricated `writesFrozen:true` is no longer sufficient. The entrypoint is **not wired into the Cloudflare production Worker**; nothing is auto-installed or auto-acquired by an environment switch.

Canonical HMAC-SHA256 attestation updated from `ledger-attestation.v1` to **`ledger-attestation.v2`**. Each table HMAC now binds the `freeze_id` and table domain as well as the complete normalized contents, preventing cross-epoch recycling of unchanged table digests. `transfer.v2` is the matching reconciliation receipt; the pre-cutover guard rejects legacy v1 receipts, performs two complete evidence comparisons and requires provider-backed **live** source-fence probes immediately before and after cutover. A lost exclusive-lease release after a successful promotion now attempts fallback to SQLite; a failure to establish fallback reports **CRITICAL**.

## Real fixture evidence, not production proof

The Node 22 native SQLite tests run real, fully installed triggers against an isolated in-memory database (NOT a mocked trigger query). They verify all five table mutation denial, atomically consistent frozen read, keyed attestation, owner identity, missing installation rejection, concurrent lease refusal, authenticated release, stale-lease rejection, restored write access after expiry and exact trigger body tampering. Unit tests verify the promotion guard's two fresh source-fence probes, postcutover rollback on lease loss, ambiguous CAS, and lease release failure handling. Offline tests do NOT prove Cloudflare-hosted locking, signed browser identity, actual provider receipt authenticity, real data recovery, or R2 object integrity.

## Mandatory before any live installation

A production owner-approved deployment would require all of the following: real signed Access identity derived by the currently verified V0.3 Worker, independently authenticated Access policy and sole owner membership, provider-backed DO PITR and an independently tested full restore on separate infrastructure, a guaranteed 300-second worst-case freeze with proven behavior if it expires during export/Neon import, documented operator monitoring, a safe maintenance notice, and a provider-backed immutable external export receipt. Explicitly rehearse rollback with *real* Cloudflare hosted data recovery while preserving every audit event and existing R2 reference. Never export live source rows to logs, GitHub artifacts, git history, public object storage, or chat. Never enable CPU/GPU rendering or relax Neon's public-network prohibition to make tests pass.

This staged control alone is insufficient to authorize production migration. Protected Cloudflare-to-Neon connectivity, genuine hosted source export, independently revalidated provider receipts, live R2 checks, verified imported-target hosted recovery, postcutover signed browser and enforceable account-level spend boundaries remain **NO-GO** requirements. The original Cloudflare SQLite DO is unchanged, and Axiom main / Studio V0.2 / staff Access are untouched.
