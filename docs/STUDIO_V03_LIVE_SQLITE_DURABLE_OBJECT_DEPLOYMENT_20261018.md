# MUSITU Enterprise Studio V0.3 — Deployed SQLite Durable Object Alternative
**Date:** 18 October 2026 (UTC). **Branch:** `experiments/studio-enterprise-v03-sqlite-do-20261018`. **Service:** `musitu-studio-v03-do`. **Public hostname:** `https://studio-v03.mftintelligence.com/`.

## Scope and architecture
The original V0.3 D1 implementation remains available and unmodified on `experiments/studio-enterprise-v03-d1-20261018` as a source-only alternative. The D1 provisioning blocker was **removed** by deploying a new SQLite-backed **Cloudflare Durable Object** rather than creating another D1 database. This is a supported Workers Free offering (subject to free-tier compute/row/storage quotas). The DO provides transactional SQL, custom schema, a single isolated Studio ledger, atomic D1-compatible adapter semantics, and persistent records once the first authenticated staff request initializes the object. **No D1 account database was created.**

The isolated Worker is `musitu-studio-v03-do`; its DO namespace binding is `STUDIO_LEDGER` with `new_sqlite_classes:["StudioEnterpriseSqliteLedger"]`. It holds the five V0.3 tables (projects, memberships, jobs, assets, immutable audit_events) created from the same V0.3 SQL migrations, with explicit schema-version tracking and Workerd `transactionSync`. It reuses only the dedicated Studio R2 bucket, but all V0.3 file writes use the distinct `studio-v03/jobs/` object prefix. It does not import the V0.2 single-admin R2 control state or touch Axiom systems.

## Android staff operations
1. In Android Chrome open **https://studio-v03.mftintelligence.com/** and complete the existing approved email-only Cloudflare Access login. Do **not** share login codes, Access callback URLs, cookies or JWTs.
2. Tap **Connect / Refresh**. After a real approved staff Access session, the first app API request initializes the persistent SQLite Durable Object ledger if not initialized.
3. Create a project, use **Copy my staff ID** (share privately) for a second allowed staff person; invite that person as `reviewer` in your project's **Team** section. Project creator cannot approve their own renders.
4. Scene submission and reviewer approval workflows are enabled by the code, but the CPU **Dispatch** button remains disabled while budget and Modal runtime gate are closed. Do not infer production GPU support from V0.2 local/Modal hardware.
5. Prior completed V0.2 Blender/R2 renders live under the old `studio.mftintelligence.com`, **not** automatically copied to V0.3.

## Rollback and maintenance
If the new hostname behaves unexpectedly, disable only the new V0.3 custom domain routing while keeping the original V0.2 Worker/domain untouched. Restrict or remove only the new `MUSITU Studio Enterprise V03` Access application after any live sessions expire. The exact V0.3-only WAF rule can be removed without changing the global `under_attack` zone setting; never delete V0.2/Axiom rules.

SQLite-backed Durable Objects support point-in-time recovery; use the Cloudflare provider facility and a restored isolated test object to qualify restore **before** enterprise-wide launch. Avoid deleting the DO namespace without a verified backup. The Workers Free plan has daily hard usage quotas; beyond those quotas operations can fail rather than silently turn into an unlimited-cost service. On a paid plan, metered usage may incur charges. Review Cloudflare account billing controls before scaling.

V0.3 live code must be redeployed using the protected GitHub workflow that reconstructs the **actual** Access audience and team domain at runtime; the checked-in Wrangler config intentionally holds invalid Access placeholders so ad hoc deployments fail closed. Do not bypass Cloudflare Access or enable GPU solely to increase features.
