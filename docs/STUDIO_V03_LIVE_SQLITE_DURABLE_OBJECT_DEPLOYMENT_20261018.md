# MUSITU Enterprise Studio V0.3 — Deployed SQLite Durable Object Alternative
**Date:** 18 October 2026 (UTC). **Branch:** `experiments/studio-enterprise-v03-sqlite-do-20261018`. **Service:** `musitu-studio-v03-do`. **Public hostname:** `https://studio-v03.mftintelligence.com/`.

## Scope and architecture
The original V0.3 D1 implementation remains available and unmodified on `experiments/studio-enterprise-v03-d1-20261018` as a source-only alternative. The D1 provisioning blocker was **removed** by deploying a new SQLite-backed **Cloudflare Durable Object** rather than creating another D1 database. This is a supported Workers Free offering (subject to free-tier compute/row/storage quotas). The DO provides transactional SQL, custom schema, a single isolated Studio ledger, atomic D1-compatible adapter semantics, and persistent records once the first authenticated staff request initializes the object. **No D1 account database was created.**

The isolated Worker is `musitu-studio-v03-do`; its DO namespace binding is `STUDIO_LEDGER` with `new_sqlite_classes:["StudioEnterpriseSqliteLedger"]`. It holds the five V0.3 tables (projects, memberships, jobs, assets, immutable audit_events) created from the same V0.3 SQL migrations, with explicit schema-version tracking and Workerd `transactionSync`. It reuses only the dedicated Studio R2 bucket, but all V0.3 file writes use the distinct `studio-v03/jobs/` object prefix. It does not import the V0.2 single-admin R2 control state or touch Axiom systems.
