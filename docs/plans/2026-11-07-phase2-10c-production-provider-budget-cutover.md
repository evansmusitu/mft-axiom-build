## Non-negotiable security contract

1. **Complete inventory, then enforce everywhere.** Enumerate live Worker scripts, routes, service bindings, schedules, queues, environment/secret bindings and provider egress. Pin deployment source commit and account/environment identity. No user-visible or internal paid request may use raw first-party adapters, direct vendor fetch, a per-Worker SQLite counter, a missing ledger, a default cap, or an unknown model price. A missing/unknown entrypoint is a blocker, not an automatic PASS.
2. **One authoritative, transactional PostgreSQL budget.** All approved billable entrypoints, tenants, models and vendor organizations must share the same approved database *authority*, not merely similarly named databases. No fallback to D1/SQLite/memory or alternate pool if connectivity, auth, schema, SQL grants or cap lookup fails. Treat 5xx, transaction lock timeouts, unknown policy and disconnections as **deny-before-paid-network**, with an observable generic error and privacy-safe audit receipt.
3. **Separate runtime and administration.** Provisioning/migration owner creates tables and immutable tenant/vendor caps; a non-owner, non-admin runtime may only perform audited reserve/settle/status functions. Protect cap columns and counter-integrity operations from direct unauthorized writes; use controlled DB privileges or appropriately reviewed server-side functions rather than assuming a TypeScript `operator-only` method is an authorization boundary. Test `SET ROLE` membership, table ownership, PUBLIC grants, default privileges, RLS bypass and role escalation. Reconcile legacy NULL `billing_provider` rows under independent operator audit; do not auto-reset spend.
4. **Verified origin, not cosmetic TLS.** Hyperdrive origin must be separately attested for hostname-verified `verify-full`, approved CA, cache **disabled** for authoritative accounting, least-privilege credentials, reasonable connection/statement/lock limits and bounded rollback. Origin configuration evidence is distinct from the Worker's dynamically supplied Hyperdrive connection string. The current Workers-only account has no verified private link; shared Cloudflare CIDRs do not identify this tenant. **Do not remove the Neon public network block or add a staging exception without an explicit risk-approved, time-bounded operator authorization and rollback plan.**
5. **Correct financial bounds.** Maintain immutable price/version mapping per billed vendor account/project, rate class and model. Require positive valid billable rates plus verified nonnegative cache rates and a conservative, *worst-case* token/request reserve ceiling. Unknown units, zero/missing ceilings, vendor identity mismatches, cap exhaustion, overages and stale rates deny spending. Keep ambiguous reservations held for reconciliation; never automatically replay a possibly charged upstream request. Reconcile actual OpenAI/Anthropic charged usage and invoices, not only mock response tokens.

## External sequencing and hold conditions

- **Staging exception gate:** obtain explicit security review and owner authorization *before* any internet-reachable Neon exception, credential creation/use or Hyperdrive binding. With public connectivity blocked, no live connection claim is possible. Do not publish secrets, private history, customer records or endpoint credential responses in logs, PRs or public docs.

G3–G5 remain separate external gates; G6 remains a private-source-history metadata/privacy gate in #75. Never merge a documentation checklist into a claim of readiness; do not close either issue or enable production based on this plan.
