# MUSITU Mail Fabric v0.3 — Isolated Distributed Infrastructure

Date: 2026-10-09. Branch: `product/musitu-mail-fabric-isolated-20261009`.

## Implemented and verified in isolated tests

* Cloudflare Workers-compatible HTTP, Queue and Scheduled handlers (`src/edge/worker.mjs`). Single-tenant explicit environment configuration. No hostname or live deploy.
* D1-backed durable enqueue, atomic claim with fencing token, encrypted envelope, suppression, provider-acceptance receipt, recovery of expired claims to `OUTCOME_UNKNOWN`, and scheduled recovery scan.
* Queue delivery is a performance hint, **not** the source of truth. Lost Queue publication leaves the record in D1; scheduled recovery can subsequently process it. Redelivery never sends twice after a persisted provider acceptance. `SENDING` lease expiry marks `OUTCOME_UNKNOWN` instead of resending.
* Authenticated Resend Svix-HMAC webhook verification using the original raw payload, signature version, constant-time comparison, five-minute timestamp limit, replay key, and persistent event deduplication.
* Provider observations are persisted separately. `email.delivered` means **provider-reported delivery**, never proof of inbox placement or human reading. Each authenticated observation is incorporated into a separately signed export with content SHA-256, no raw recipient address.
* Worker uses supplied persistent signing keys; mismatched private/public keys are rejected before any transaction. Query `/v1/keys/current` requires tenant authorization and exposes the public key for **out-of-band fingerprint pinning**.
* Restricted bearer-authenticated interface: `POST /v1/messages`, `GET /v1/messages/:uuid`, `GET /v1/messages/:uuid/evidence`, `GET /v1/keys/current`. Mail intake is disabled by default until explicitly enabled.
* Non-production SQLite D1 emulation covers concurrent claim, restart, unknown send, replay, forged webhooks, unauthorized access, wrong tenant, crypto key mismatches, and queue failure. Mailpit loopback integration is run in GitHub Actions where the service is available.

## Proposed isolated Cloudflare configuration

`wrangler.mmf.template.jsonc` defines a **new dedicated** D1 binding, a new outbound queue plus a dead-letter queue, disabled Workers.dev hostname, no assigned route, disabled send flags, and a five-minute scheduler. Nothing in the template can provision or migrate an existing AXIOM database.

Secrets to provision exclusively in isolated runtime after independent authorization: `MMF_AUTH_TOKEN` (>=32 chars), `MMF_ENCRYPTION_KEY_B64` (32 random bytes), `MMF_PRIVACY_KEY_B64` (>=32 bytes), `MMF_SIGNING_PRIVATE_KEY_PEM`, `MMF_SIGNING_PUBLIC_KEY_PEM`, `MMF_RESEND_API_KEY` (optional when enabling real send), `MMF_WEBHOOK_SECRET` (Resend whsec_...), plus selected tenant/sender configuration. Key generation, key custody and trusted public fingerprint publication are an **operations prerequisite**, not part of this repository.

## Readiness and risk boundaries

* No customer emails sent, no DNS changed, no sending provider credentials accessed and no production deployment performed during v0.3 build.
* The provider region is an **operator-supplied setting**, not a residency attestation.
* Queue semantics are at-least-once; the prototype protects against duplicates within the available SQL state but has not proven multi-region scale, total deliverability, or distributed chaos scenarios.
* Provider event proof validates **MUSITU's signature on a persisted authenticated provider report**, not third-party legal certification. Trust anchors need independent pinning, revocation, key rollover and possibly third-party timestamp services.
* Pending before customer traffic: real isolated Cloudflare provisioning, D1 schema migration proof, load and chaos tests against live Workers/D1/Queues, verified webhook endpoint registration, durable dead-letter monitoring, regulated-data review, sender DNS/consent controls, rate limits, tenant-scoped key storage, signing-key rotation, billing and abuse controls, independent security review, human-on-call agreements.
* Credentials are never committed; full production and frozen OpenAI submission remain untouched.

## Competitive outcome

This is a verifiable pre-production engineering milestone, not evidence MUSITU Mail Fabric is the first or best global email provider. The commercial moat requires paid pilots, independent cryptographic verification, standards interoperability, real reputation data, and externally measured service performance.

## Offline evidence verification and a second delivery adapter

- `src/verify-cli.mjs` verifies an exported evidence JSON against a separately obtained **pinned** public key: `node src/verify-cli.mjs --receipt receipt.json --trusted-key trusted.pem`. Missing trust anchors, tampering or an untrusted signing key yield a nonzero exit and `INVALID_EVIDENCE`/`TRUST_ANCHOR_REQUIRED`. Does not assert inbox delivery.
- `createPostalProvider` is an opt-in HTTPS-only adapter for a separately operated Postal service. Worker selects it only with `MMF_REAL_SEND_ENABLED=true`, `MMF_PROVIDER=postal`, `MMF_POSTAL_BASE_URL` and `MMF_POSTAL_API_KEY`. Provider ID is normalized to an opaque digest to avoid leaking transport internals. No Postal server was installed and no Postal email was actually sent.
- Resend remains an alternate opt-in adapter, selected by `MMF_PROVIDER=resend`; no default real sending. Provider switching is **configuration**, not automatic rerouting following ambiguous acceptance.
