## Implemented modules

- `src/edge/sqlite-do.mjs`: secret-authenticated read-only `/stage-pitr-capability` available solely under stage flags. Returns a cryptographic digest of the current Cloudflare PITR bookmark, never the raw bookmark. No restore, rollback or destructive PITR endpoint.
- `src/edge/worker-do-staging.mjs`: synthetic-only private Queue probes for PITR, operational health and feature-gated expired-claim reconciliation. Public `fetch()` continues to return 404.
- `src/ops/health.mjs`: read-only tenant-scoped metrics of queued, sending, provider-accepted, rejected, ambiguous, suppressed-by-policy states; expired delivery claims, oldest pending, bounce and complaint counts. Does not include email recipients, sender addresses, contents, provider IDs or access tokens.
- `src/edge/worker.mjs`: opt-in `GET /v1/ops/health` for a **separate operator bearer token**. It remains disabled unless `MMF_DIAGNOSTICS_ENABLED=true`. Customer bearer tokens cannot access it, and reporting remains possible while delivery is paused.
- `src/edge/synthetic-transaction.mjs`: preflights every staging SENDING row as a synthetic `probe-...` idempotency key; refuses all maintenance if any row violates scope, then invokes durable `reconcileExpired()`. It never invokes a provider send or resends ambiguous network attempts.
- `wrangler.mmf.do-staging.jsonc`: additionally gates private synthetic reconciliation with `MMF_STAGE_RECONCILE_ENABLED=true`; customer API, sending and webhook intake remain disabled.

## Security and correctness constraints

- Only synthetic probes may trigger the read-only or claim-reconciliation functions. A non-probe row prevents any reconciliation mutation.
- Provider API acceptance is never represented as inbox delivery. Historic in-flight sends with expired leases become `OUTCOME_UNKNOWN`, not `ACCEPTED_BY_PROVIDER` or `QUEUED`.
- The staging reconciliation is not a general automatic retry engine. It exists to resolve historical synthetic staging claims after previous Cloudflare/D1-compatibility defects.
- The Cloudflare PITR bookmark confirms availability of the documented infrastructure API, but **does not demonstrate a restored database, 30-day recoverability for the exact application, integrity of a restoration, cross-region resilience, or recovery from a genuine provider outage**.
- Staging secrets are disposable Cloudflare Worker Secrets, not customer-owned HSM/KMS/backup-attested long-term key custody. External legal trust certification has not been obtained.
- Cloudflare D1 provisioning previously failed due to the account's free database count limit. Staging uses an isolated SQLite Durable Object rather than modifying AXIOM's databases or purchasing an upgrade.
