# MUSITU Mail Fabric v0.12 — Recipient-Bound Webhook Security and Early-Event Reconciliation

**Date:** 2026-10-10 UTC  
**Authority:** isolated source branch `product/musitu-mail-fabric-isolated-20261009`. No customer sending or public Mail Fabric endpoint has been enabled. The OpenAI review snapshot and protected AXIOM resources were not modified.

## Resend 2026 event contract

Resend's 2026 webhook contract produces individual recipient delivery outcomes with `data.to` still represented as a single-element array. Official source: https://www.resend.com/changelog/webhook-event-visibility . Therefore **a valid Svix signature and matching provider email ID alone are insufficient to establish that an outcome belongs to the correct transaction recipient**.

### Implemented security controls

1. **Strict recipient attribution for the real Worker webhook:** `POST /v1/webhooks/resend` now requires exactly one syntactically valid signed `data.to` recipient. Its normalized address must match the tenant-specific `recipient_hmac` on the originally provider-accepted Mail Fabric transaction. Mismatches produce HTTP **422**, malformed/missing recipient claims **400**, and neither condition may create a provider event or suppress a recipient. Unauthenticated signatures still return **401**. Existing helper callers may explicitly choose the legacy non-strict parser for local compatibility; the production-facing Worker selects strict mode unconditionally.
2. **Transactional recipient suppression:** a correctly signed and attributable bounce/complaint durably records a provider event, suppresses only the recipient in the original transaction, and blocks future sends. Identical Svix retries remain idempotent and conflicting event IDs fail closed.
3. **Retryable early-arriving signed webhooks:** when the signed event's provider email ID has not yet been durably attached to an accepted transaction, the strict Worker now returns HTTP **503** `PROVIDER_CORRELATION_PENDING` rather than falsely returning **202**. The *identical signed event* can then succeed after the simulated provider acceptance is durably stored. Resend supports automatic retries, manual replays, and headless event/attempt inspection; see https://www.resend.com/features/webhooks and https://resend.com/changelog/headless-webhook-api . **This relies on the provider's retry window; an event that never retries remains unverified until a separate provider-log reconciliation process is qualified.**
4. **Synthetic stage isolation:** test-only messages now address per-probe pseudonymous recipients, preventing a successful synthetic bounce from suppressing every subsequent staging probe. The existing historical suppression is preserved; no production or staging suppression records were silently cleared.
5. **Separate operational secrets:** stage feedback uses a freshly generated, ephemeral, local-only synthetic Svix signing secret. It is not a Resend account signing secret and is not shared in CI logs.

## Actual cloud evidence

[GitHub Actions 38036274546](https://github.com/evansmusitu/mft-axiom-build/actions/runs/38036274546) **succeeded** on the existing private Cloudflare Queue and SQLite Durable Object. Its evidence gate `MMF_CLOUD_REAL_SQLITE_SYNTHETIC_RESEND_RECONCILIATION=PASS` established signature and recipient matching, mismatch rejection, exact replay idempotency, durable bounce suppression, and rejection of a later send to the suppressed recipient. The cloud path used a *simulated* provider and a synthetic signed webhook created by MUSITU test code, **not an event generated by the real Resend service**. No customer email was sent.

A separate early-feedback Cloudflare qualification [GitHub Actions 38036623884](https://github.com/evansmusitu/mft-axiom-build/actions/runs/38036623884) did **not** pass: previous stage tests had suppressed the shared synthetic recipient. The defect was fixed by per-probe test recipient isolation, with additional shared-database regression tests. Follow-up isolated GitHub regression workflows succeeded; **the corrected early-race path has not yet produced a successful fresh cloud requalification**, and must not be represented as live-cloud-proven.

## Verification and nonclaims

- `test/webhook-recipient-identity.test.mjs`: correct signed address, forged mismatches, missing/multi-recipient claims, tampered signatures, idempotency and suppression.
- `test/webhook-early-retry.test.mjs`: an unmatched signed event gets a retryable error before provider acceptance, then records exactly once after acceptance, including when outgoing traffic is paused.
- `test/stage-synthetic-feedback.test.mjs`: complete encrypted outbox -> synthetic provider ID -> Svix-signature validation -> tenant-scoped SQLite -> evidence -> suppression, plus persistent-stage probe isolation and early-event replay.
- `test/release-authorization-v08.test.mjs`: an expired dual-party live-send grant cannot silently acknowledge an unmatched but signed webhook.
- Successful branch CI is *internal verification*, not an external security assessment.

## Remaining genuine launch requirements

- A verified, customer-authorized real Resend/Postal webhook endpoint. The connected Resend account had **no registered webhooks** at the last read-only inspection, and Mail Fabric intentionally has **no public inbound route** in the isolated staging deployment.
- Controlled provider sending to approved test recipients, actual provider-originated signed event and bounce/complaint attribution, and inspection/replay via Resend's actual event API. Do not mistake self-signed test fixtures for live provider feedback.
- Recoverable customer-owned encryption/signing keys, verified backups across provider/account loss, retention controls, legal/consent and suppression policy review, independent penetration testing and signed external assessment.
- Operationally verified metrics for backlog, unknown outcomes, failed webhook retries, volume limits, billing, SLOs and an explicit commercial release gate.

This release addresses practical webhook-attribution and timing defects while preserving the established private staging safety perimeter. **Commercial production readiness is NOT claimed.**
