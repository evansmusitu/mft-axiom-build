An isolated incremental build on `product/musitu-mail-fabric-isolated-20261009`. ## New trust invariant

A communication receipt must be verified against an **independently pinned** Ed25519 genesis public key **and** independently pinned latest rotation-chain SHA-256 hash. Keys are transitioned with predecessor and successor signatures over a strictly ordered, tenant-specific statement containing epoch, predecessor fingerprint, previous SHA-256 head, successor public key and declared timestamp. Offline validation checks every transition in order, strict fields, both signatures, tenant scope, previous hash and head equality, requiring the receipt to use the currently authorized key.

No automatic public key discovery is treated as an independent trust anchor. This first format intentionally **rejects historical receipts signed by a previous key** if the trust chain has moved forward, because current proof-v1 receipts do not have authenticated issuance epochs. Future proof-v2 must bind issuance epoch and trusted timestamps to distinguish lawful historical receipts from fraudulent post-rotation backdating. An asserted rotation timestamp is not a qualified timestamp, and self-issued rotation history alone is not a public key transparency service. Independent publication, anti-equivocation, revocation/recovery, escrow and multi-party custody remain production requirements.

CLI (offline only):

`node src/trust/verify-cli.mjs --receipt proof.json --root-key pinned-root.pem --transitions signed-rotations.json --trusted-head independently-known-sha256 --tenant authorized-tenant`

Returns 0 only on current authorized signature and intact evidence; 1 for tampered/untrusted evidence, 2 for missing/invalid arguments. Does not claim SMTP handoff, inbox delivery, identity of reader, legal service of notice or external timestamp attestation.

## Local Cloudflare Worker+D1+Queues integration

`wrangler.mmf.local.jsonc` is **not a deployable production config**: its entrypoint is `src/testing/worker-local.mjs`, the Worker never sends external email, generated keys are ephemeral for local-only proof, a fake D1 ID is used and the application has no public route. GitHub Actions v0.5 CI provisions the D1 schema in Wrangler's local-only state, starts `wrangler dev --local` on 127.0.0.1, posts a synthetic authenticated transaction, confirms idempotency and that the queue consumer processes the message exactly once, then reads a signed evidence chain. The local test uses no production secrets or network sender API.

This integration test must be observed **PASS in GitHub Actions** before claiming that the actual Cloudflare local emulator passed; source code alone does not prove it. Free Queues allow 10,000 operations/day with 24-hour retention; the database remains authoritative and recovery scan repairs lost queue signals.

## Remaining formal production gates

Explicit isolation authorizations for separate Cloudflare D1/Queue/Worker resources; real cloud API capability and billing-tier verification; durable encryption and signing key custody/rotation; independent trust-head publication; third-party sender DNS proof; real provider webhooks with abuse/complaint handling; load and crash recovery against genuine cloud D1; rate limits and sender identity verification; verified consumer permissions/retention; anti-spam controls; operational incident coverage; legal and data-residency review; and externally measured deliverability and customer adoption. Until these gates pass, default fail-closed: no customer sending, no public routes or SLA claims.
