# v0.7.1 isolated managed-secret cryptographic qualification

## Scope
The only live worker is `musitu-mail-fabric-staging-20261010`, disabled for public access. Its queue is `musitu-mail-fabric-staging-20261010`. All customer sending and webhook admission are disabled by immutable staging flags. Only synthetic random probes are permitted. This product is not publicly launched.

## Key provisioning boundaries
CI creates a disposable staging Ed25519 PKCS#8 signing key and an independent 32-byte AES-GCM data key using cryptographic randomness. These are stored under `MMF_STAGE_SIGNING_PRIVATE_KEY_PEM` and `MMF_STAGE_DATA_KEY_B64` as Cloudflare Worker secrets, not in GitHub secrets or repository source. The workflow checks secret names before writing; partially provisioned keysets fail closed to prevent silent rotation. The CI runner does not archive private material, so these are disposable staging-only credentials and **must not be used for customer data**.

## Proof
A Queue `MMF_STAGE_PROBE` message generates a fresh nonce, encrypts/decrypts a synthetic string with AES-256-GCM, signs/verifies SHA-256 of the string with Ed25519 and logs only `cryptoVerified`, the public-key SHA-256 fingerprint and a private SQLite probe readback. The Worker publicly returns 404 and has no workers.dev previews or routes. Runtime secret access is verified only through that synthetic proof. Provider delivery, live mail, externally pinned trust registry, backup-validated rotations, retention policy, legal compliance, KMS/HSM custody and independent penetration-testing remain unverified.

## Operational guidance
The keys must not be used as an independent trust anchor without verified key history, dual approval, non-production key escrow and revocation design. Unknown or missing secrets cause Queue retries rather than falsely reporting success. Never enable external messaging or expose the staged Worker to the public.
