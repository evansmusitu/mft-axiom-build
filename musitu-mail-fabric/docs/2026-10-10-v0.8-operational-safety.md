# MUSITU Mail Fabric v0.8 — Operational Sending Safety (2026-10-10)

Isolated software qualification only. No public sending or customer API is enabled by this change.

## Implemented controls
- Single-statement, UTC fixed-minute rate ceiling at enqueue: `minuteSendLimit` defaults to 20 messages per tenant per minute (1–1000). The Worker operator binding `MMF_MINUTE_SEND_LIMIT` overrides this; it cannot be set by the HTTP message body. Existing daily and per-recipient quotas remain enforced in the same atomic SQLite insert.
- Exceeded burst ceiling returns HTTP 429 `RATE_LIMIT_EXCEEDED`, while previously accepted matching idempotency keys return their original transaction. The check also survives new worker instances because it uses durable SQL state.
- Configurable maximum age of a queued message `maxQueuedAgeMs`, default 86400000 (24 h), permitted 60000 through 604800000. Worker binding is `MMF_MAX_QUEUED_AGE_SECONDS` (60–604800). A stale queued message is permanently `BLOCKED_BY_POLICY`, sealed payload is erased, and no provider network request occurs. Signed evidence records `blockReason: QUEUE_EXPIRED`.
- Invalid operator configuration fails closed; no real provider or domain was activated. All new tests use only simulated transport and native SQLite.

## Limits and follow-up gates
This is a **fixed UTC minute window**, not a sliding 60-second window or globally distributed token bucket. Up to twice the limit may occur near a minute boundary; configure conservatively. It does not substitute for bot protection, abuse investigators, spam/phishing detection, complaint-rate thresholds, lawful sending consent, business verification or independent security assessment.

In-process provider send operations may continue after clock time advances; expiration is checked before each provider call, not cancellable mid-flight. Expired in-flight leases remain classified as outcome unknown rather than retried.

Production sending is still disabled. Independent cloud validation of the final integrated customer Worker, real authenticated provider events, long-lived key custody, disaster recovery and third-party security sign-off remain outstanding.
