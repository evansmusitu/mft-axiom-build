# MUSITU Mail Fabric v0.9.0 — Encrypted offline disaster recovery

**2026-10-10 · Private, isolated engineering capability. Not a production backup service.**

## Scope

MUSITU Mail Fabric now implements `src/ops/backup.mjs` and `src/ops/backup-cli.mjs`, a synchronous **offline SQLite** encrypted export / independently pinned signing-key verification / fresh-database atomic restore path. The target source is a separately exported SQLite file; this is **not** a Cloudflare Durable Object cloud snapshot API, managed backup schedule or evidence of an actual provider outage.

A tenant's rows from `mail_messages`, `mail_suppressions`, `mail_sender_domains` and `mail_provider_events` are captured with a SQLite `BEGIN IMMEDIATE` transaction. A unique AES-256-GCM nonce and a separate backup key encrypt the entire tenant-scoped manifest. Ed25519 signs the exact backup metadata and ciphertext. Restore refuses the wrong tenant, backup key, pinned signer, message-encryption key or recipient HMAC/privacy key. Every restore operates inside a transaction on a **new empty database** and rolls back on a failed insert, relational-integrity check or tampering.

The stored `sealed_envelope` remains an encrypted pending message. The original payload encryption key is required to recover and decrypt pending messages. Existing `SENDING` rows are **not** automatically changed to `QUEUED` during restore: network acceptance might have occurred, so human-led reconciliation is required. No automatic cross-provider retry may be inferred from this backup.

## Local CLI

Use **Node.js 22+**, a local SQLite backup copy and a separately trusted Ed25519 PEM pair. The operator must explicitly set `MMF_BACKUP_OFFLINE_ACK=I_ACKNOWLEDGE_OFFLINE_RECOVERY` before executing any operation.

Secrets must be provided via the process's secure secret environment, **never through CLI arguments or committed files**:

- `MMF_BACKUP_KEY_B64`: independently generated 32-byte AES-GCM backup key (base64).
- `MMF_ENCRYPTION_KEY_B64`: original Mail Fabric message encryption key, 32 bytes (base64).
- `MMF_PRIVACY_KEY_B64`: original HMAC privacy key, 32 bytes (base64).

Do not copy actual key values into documentation, CI logs or ChatGPT. Use a properly protected secret manager. For a newly created staging test, independently generate keys and safely retain the recovery material.

```bash
cd musitu-mail-fabric
node src/ops/backup-cli.mjs export /isolated/stage.sqlite client1 /secure/stage.mmf.json /secure/stage-private.pem /trusted/stage-public.pem
node src/ops/backup-cli.mjs verify /secure/stage.mmf.json /trusted/stage-public.pem
node src/ops/backup-cli.mjs restore /secure/stage.mmf.json client1 /isolated/empty-restored.sqlite /trusted/stage-public.pem
```

The CLI will refuse to overwrite an existing backup archive or restored database and creates new files with restrictive permissions. Verification requires a **pinned external public key**. The restore integrity gate checks `PRAGMA integrity_check` and the schema's foreign keys. Only redacted status codes and record counts are printed.

## Non-goals and production blockers

1. **Cloud backups and natural outage recovery:** Cloudflare's actual SQLite Durable Object storage is not directly exported by this CLI. A separately authorized, encrypted and bounded cloud snapshot job plus cloud-to-offline and offline-to-isolated-cloud restoration drills remain necessary. Never attach this tool to production without appropriate approvals.
2. **Managed custody:** Cloudflare staging Worker secrets are disposable and not a customer-owned KMS/HSM with independently verified key escrow, rotation, recovery or root pinning.
3. **External provider validation:** No real Resend/Postal delivery, bounce or complaint webhook round-trip from a controlled mailbox was validated by this change.
4. **Independent security evaluation:** No external named assessor's signed report exists. Internal tests do not satisfy that prerequisite.
5. **Customer lifecycle:** Consent, anti-abuse operational review, regional legal obligations, data retention/deletion, monitoring, SLAs and customer contracts remain open.
6. **Data portability limitations:** Export is capped at 8 MiB of uncompressed tenant data and 20,000 rows per table. It requires a synchronous SQLite file and no concurrent on-cloud backup shortcut. Key loss prevents recovery; provider accepted is never human inbox delivery.

All work remains on `product/musitu-mail-fabric-isolated-20261009`. Public sending, live support operations and the frozen OpenAI surface remain unchanged.
