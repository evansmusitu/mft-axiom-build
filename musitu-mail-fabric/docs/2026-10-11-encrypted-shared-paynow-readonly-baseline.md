# Shared Paynow two-Worker source/settings: owner-authorized, GET-only, encrypted source baseline

**Classification:** Sensitive restoration material, NEVER public plaintext. **Scope:** `mft-phase8-external-authority` and `mft-paynow-transport-gateway`. No mutation to shared Workers, merchant credentials, bindings, payment provider or customer records.

This isolated GitHub workflow reads each Worker script twice through authenticated GET, normalizes Cloudflare multipart representations and requires matching normalized source digests; then it GETs `/settings` for exact, opaque settings metadata. If either Worker is unavailable or changes between two reads, it refuses the entire backup. The full raw source GET payload (including multipart) and full `/settings` JSON are encrypted **in memory** with AES-256-GCM; the AES key is wrapped to a locally generated RSA-3072 public recovery key via OAEP-SHA256. The public GitHub artifact contains ONLY ciphertext, RSA-wrapped key and nonsecret digests. The matching RSA private key is not part of GitHub or any handoff ZIP.

**Operator recovery requirement:** Keep the local private recovery key separately in secure owner custody. Without it, the artifact is **unusable**. `unsealMmfSharedWorkerBackup(sealed, privateKeyPem)` decrypts and verifies the two exact source digests. The runtime does not automatically decrypt or deploy these files. Any restoration requires separate approval, exact source deployment method verification, review of Cloudflare version/DNS/service bindings, merchant secret custody and actual rollback rehearsal. Cloudflare `secret_text` **values are not exported** in the settings GET and MUST be recovered from existing secure secret custody. This ciphertext is thus a protected **source/settings restoration candidate**, not verified complete production disaster recovery.

No Cloudflare POST/PUT/PATCH/DELETE, no Paynow requests, no unredacted source in logs, no changes to PR #1/main/FMI/Axiom/Chemistry. Owner permission covers integration engineering and this GET-only snapshot, not independent production-release signoff or a real payment. The MMF stage admission probes remain default OFF.

**Commands:** `npm run test:mmf-shared-backup`, `npm run check`, `npm test`. New GitHub Actions workflow is branch-scoped and uses existing protected `axiom-support-production` environment; its successful run must be verified at the exact commit and the sealed artifact must be downloaded, decrypted locally and hash-verified before calling the baseline captured.
