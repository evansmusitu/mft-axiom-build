# MMF-specific private authority staging boundary — October 11, 2026

This implementation adds a **new, distinct, route-disabled** Cloudflare Worker for MMF authority staging. It is **not** an amendment of `mft-phase8-external-authority`, `mft-paynow-transport-gateway`, `mft-fmi-billing`, Axiom, Chemistry, or public DNS. The only new service binding is `MMF_PRIVATE_PAYMENT_STAGE -> musitu-mail-fabric-payment-private-stage-20261011`.

## Design and safety controls

- No real Paynow merchant key, merchant integration ID secret, provider callback endpoint, `/internal/paynow/initiate`, checkout, refund submission, invoice, or payout capability exists in the new Worker. The Worker cannot call live Paynow.
- The stored deployment has `workers_dev=false`, `preview_urls=false`, `routes=[]`, no incoming public route, no additional service binding and **no database binding**. It has no D1 consumption, uses the existing **isolated** MMF billing stage only, and does not connect to customer databases.
- Default flags: `MMF_PRIVATE_AUTHORITY_STAGE_ENABLED=false`, `MMF_STAGE_BRIDGE_ENABLED=false`, `MMF_STAGE_RECEIPTS_ENABLED=false`, `MMF_COMMERCE_ENABLED=false`, `MMF_REAL_SEND_ENABLED=false`, `MMF_MAIL_SENDING_ENABLED=false`, `MMF_API_ENABLED=false`, `MMF_WEBHOOK_ENABLED=false`.
- Synthetic-only certification is **off** unless all three stage flags are true, the bridge credential is separate from the billing operator and receipt bearer, a server-validated expiry within twenty minutes is installed, a valid MMF quote matches a fingerprint-pinned Ed25519 receipt, and the only downstream request uses the fixed service binding. Unauthorized, oversized, cross-order, forged, expired, and cross-product input fails closed.
- Even when synthetic receipt intake is temporarily enabled, responses explicitly state `realProviderSettlementVerified:false`, `canAcceptCustomerFunds:false` and `grantsMailSending:false`.
- A successful Cloudflare deployment and configuration readback proves an **MMF-private binding exists**; it does **not** prove genuine Paynow authority authorization. Real Paynow scope, independent callback/poll, legal pricing/invoicing, independent security release and separate permission for customer funds/messaging remain blocked.
