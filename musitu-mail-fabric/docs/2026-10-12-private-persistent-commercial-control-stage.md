# MMF — Persistent private customer control plane, release candidate (not deployed)

**Scope:** isolated `product/musitu-mail-fabric-isolated-20261009`. This is internal engineering evidence and contains no merchant secrets, live customer identity, or staff/owner structure.

## What is implemented

- `src/edge/mmf-commercial-private-stage.mjs`: fail-closed private stage kernel wired to the actual MMF `IdentityAdmission`, `StageCommercialController` and `CommercialPlatform` code (no second version of its product rules). SqlStorage adapter provides synchronous `prepare/get/run`, genuine `SELECT changes()` row counts, DDL via `sql.exec` and atomic `transactionSync()` operations. It deliberately does NOT execute explicit SQL transaction commands through Cloudflare's SqlStorage API.
- `src/edge/mmf-commercial-private-cloudflare.mjs`: Cloudflare RPC wrapper **extends DurableObject**. Its default Worker and the Durable Object `fetch` response are always HTTP 503 with no CORS. Public routing is intentionally absent. Only a separately authorized internal Worker with the namespace binding could invoke its private RPC methods.
- `wrangler.mmf.commercial-private.template.jsonc`: **nondeployable template** with `MMF_STAGE_ONLY=false`, all payment/sending/public API flags false, no routes, no Workers.dev/preview endpoint, new SQLite-backed DO namespace, and `nodejs_compat`. No account ID, actual OIDC provider, live signing key or secret pepper is committed.
- Existing `mmf-commercial-platform.mjs` and `mmf-oidc-admission.mjs` use the shared, synchronous `mmfTransaction` adapter to preserve SQLite ACID behavior across local `node:sqlite` and Cloudflare `storage.transactionSync`, including error rollback.

## Tests and their limits

The new tests persist a customer identity session, API key, DNS challenge and subscription to a **real local on-disk SQLite database**, close its connection, reconstruct the storage adapter and verify the same customer's access and all cross-tenant denials. They test consumed challenge replay, session revocation, exact state from `changes()`, duplicate event counting, `BEGIN` rejection, forbidden public requests and disabled checkout/sending flags.

Local on-disk SQLite with an adapter emulating `ctx.storage.sql.exec` is NOT a real Cloudflare Durable Object integration test. The genuine Cloudflare environment has **not** been deployed or connected to a real identity provider for this feature. No real customer signup or merchant payment is claimed.

## Release gates still open

1. Identify the actual, contractually approved OIDC provider; independently fetch and pin its provider signing keys and client audience, then test JWKS rotation, issuer changes, logout and login callback/PKCE/cookie protection under a reviewed gateway.
2. Provision independent, random Cloudflare secrets (`MMF_API_PEPPER_B64`, `MMF_SESSION_PEPPER_B64`, `MMF_PAYMENT_PUBLIC_KEY_PEM`, `MMF_OIDC_*`) and define operator access, backups and recoverability. Do not use the RSA/Ed25519 keys generated by unit tests.
3. Obtain explicit separate controlled staging deployment approval before a new Durable Object namespace and bills are created. No protected shared Paynow Workers or production customers may be changed.
4. Verify live Cloudflare storage behavior, PITR recovery and concurrent tenant provisioning; qualify DNS verification using an independently authorized resolver before customer domains can transition beyond `PENDING_DNS`.
5. Complete production customer gateway, CSRF/session binding, rate-limits, terms/privacy, account deletion, support contact and audit/incident controls. Confirm legal ability to invoice.
6. Paynow MMF-specific checkout and settlement, signed authentic Resend webhook reconciliation and public delivery remain disabled pending their own qualification; synthetic paid assertions never turn into entitlements.

**Status:** persistence adapter and private Cloudflare RPC code implemented and tested locally; NOT a production customer dashboard, live signup, actual payment processing or live mail delivery.
