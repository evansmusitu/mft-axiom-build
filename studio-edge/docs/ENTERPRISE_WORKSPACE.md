# MUSITU Intelligence — opt-in enterprise tenant workspace foundation

This feature is **NOT LIVE** and has no configured Cloudflare Access identity or D1 binding in existing production or canary Wrangler configurations. It does not turn the five local encrypted browser slots into cloud accounts.

## Security boundary
- URL: GET/PUT/DELETE /api/enterprise/tenants/{tenant_id}/artifacts?id={artifact_id}
- Auth: signed RS256 JWT in cf-access-jwt-assertion, validated against the configured Cloudflare Access issuer's public JWKS, exact issuer, audience, expiry, issued-at and signature.
- Authorization: on EVERY request, the signed subject must have an ACTIVE row in D1 tenant_memberships for the URL's tenant; owner/editor can write, viewer can only read. The client never sets its authorization role.
- Storage: server receives a strictly shaped opaque AES-GCM envelope (version=1, 12-byte base64url IV, base64url ciphertext including authentication tag). Server does NOT encrypt, decrypt, manage keys, validate an encryption password, or verify the plaintext. Clients must use genuine authenticated encryption with random unique IVs.
- Durable tenant-scoped rows use compound (tenant_id,artifact_id) keys. Mutation and minimal audit event are written in one D1 database transaction. The SQL statement itself checks active membership and owner/editor role, closing revoked-access races between an earlier JS lookup and database mutation; the read query joins active membership as well. Audit events are inserted only when SQLite reports a changed row. A missing DELETE returns 404 without a false audit. Delete removes ciphertext, but retains audit rows without content.
- **Concurrent editor safety: required strong ETags**. GET returns `ETag: "<uuid>"`. To create, send PUT with `If-None-Match: *`; to replace, send PUT with `If-Match: "<etag-from-last-read>"`; DELETE also requires `If-Match`. Every successful PUT rotates the revision UUID in the same SQLite statement as ciphertext mutation, so stale clients cannot silently replace or delete newer work. Mutations lacking preconditions return HTTP 428; malformed or weak tags return 400; version conflicts return 412 without ciphertext or audit mutations. Changed membership at SQL execution returns 404 instead, without exposing content. ETag is a concurrency token, **not** authorization or an encryption key. This does not implement automatic multi-device synchronization, account sessions, or offline conflict resolution.
- A **new 50-artifact per-tenant row cap** is enforced by the `0002` SQLite AFTER INSERT trigger. The same tenant can update existing records at capacity and reuse freed slots after deletion. A recognized quota abort maps to HTTP 409 `TENANT_ARTIFACT_LIMIT`. A separate `0004` SQLite trigger enforces up to **20 successful mutations per tenant in any rolling 60-second window**, before adding an audit row. Mutation and audit are committed or rejected together, and excess returns HTTP 429 `TENANT_MUTATION_LIMIT`. This is NOT a global GET/authentication/network/AI quota. This bounds *stored artifact count in the dedicated D1 database*, NOT request frequency, aggregate audit growth, AI consumption, bandwidth, worldwide cross-provider costs, or any already-deployed service. It remains inactive until the new D1 database and migration are actually provisioned and independently verified.
- No cross-origin browser access beyond the MUSITU website; browser Origin is NOT authentication. GET with `?id=<artifact_id>` reads an encrypted item; GET with no `id` now lists only bounded **metadata** (artifact identifier, revision, update time) using a maximum 10-item ordered keyset page. Optional `?after=<artifact_id>&limit=1..10` pagination is constrained and rejects mixed/duplicate query parameters. Tenant membership is checked inside the list query, and the listing never returns ciphertext or cross-tenant items. No provisioning API is exposed.
- This feature is only a foundation, NOT a production-qualified enterprise workspace. Rate caps, operational deletion policy, customer consent, backups, abuse monitoring, identity lifecycle, verified revocation latency, session control, transport and threat-model acceptance remain gating work.

## Deployment prerequisites (separate authorized resources)
1. Provision an isolated dedicated Cloudflare D1 instance, **not** any existing Neon/customer/project database; apply `migrations/0001_enterprise_workspace.sql`, `migrations/0002_enterprise_tenant_artifact_limit.sql`, and `migrations/0003_enterprise_artifact_revision.sql`, and `migrations/0004_enterprise_mutation_budget.sql` in that order there. Do not point either migration at unrelated/customer databases.
2. Provision and verify Cloudflare Access protected identity application, and configure WORKSPACE_DB binding, ACCESS_TEAM_DOMAIN (https://<team>.cloudflareaccess.com), ACCESS_AUDIENCE (actual application audience). Do not log or echo tokens.
3. Insert tenants and memberships through a separately audited administrator path, not from user-supplied tenant claims.
4. Deploy first to a NEW private canary, not the public Worker, and run valid/invalid JWT including oversized upstream JWKS, metadata pagination/revocation, tenant A/B, 20/21 mutation-rate limits, concurrent revocation, 50/51-item quota, optimistic concurrent editors (create-only, update-only, stale updates, stale deletes, replay after deletion), real D1 encrypted save/read/delete and independent security/privacy acceptance.
5. No production promotion without reviewed rollback, controls, cost and retention approval.

Existing Wrangler files intentionally do not reference WORKSPACE_DB or Access variables. Without complete configuration every enterprise API request returns NOT_CONFIGURED; ordinary public AI endpoints stay unchanged.

## Verified non-deploy test boundaries
- Real SQLite integration tests reproduce the membership revocation race and confirm SQL-statement authorization prevents writes, deletes, and reads after revocation. Membership pre-check alone was insufficient.
- SQLite migration quota tests fill two tenants independently, deny their 51st insert, permit updates at capacity, and permit inserts after deletion. Real SQLite CAS tests cover correct 428/412 responses, adversarial stale revisions, cross-tenant token mismatch, delete/recreate replay, no erroneous audit rows, and browser CORS ETag exposure.
- The local tests and CI are **not** a real Cloudflare D1 canary acceptance. No tenant can use cloud storage until an authorized Cloudflare Access application, dedicated D1 binding and live security acceptance exist.

## Additional security verification (not production)
- Adversarial tests reproduce the 21st audit mutation succeeding before the `0004` migration, then prove the database rejects it without partial ciphertext or audit writes. This is database-global only for that tenant and does not cover unsigned GET probes or aggregate model spend.
- Tests prove keyset listing pages never contain ciphertext or another tenant's metadata, and reject malformed or duplicate pagination parameters.
- Cloudflare Access JWKS is now byte-bounded to 32 KiB even if Content-Length is absent or inaccurate. The Worker rejects oversized responses *before* accepting any signing key, and tests cover the former acceptance defect.
